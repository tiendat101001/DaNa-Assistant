# Windows compatibility review (static, ~14:15 GMT+7; no Windows host available)

## HIGH
1. models/manager.py:315 `shutil.rmtree(..., ignore_errors=True)` then `store.remove` (line 316). On Windows a .tflite mmapped by a live LiteRT interpreter (or still referenced after `unload`) cannot be deleted -> rmtree silently leaves files, manifest says deleted, orphan multi-hundred-MB dir; re-pull then hits stale files. Fix: `rmtree(onerror=)` that collects failures; retry 3x with 100ms sleep (gc.collect() first); if still failing raise ModelBusyError / keep manifest entry.
2. runtime/litert.py:155-158 `close()` only sets `_interp=None`; mmap release relies on refcount and any outstanding `get_tensor` views / signature runners (self._runners?) keeping it alive. Fix: also drop signature-runner/cached-tensor refs, `del`, `gc.collect()` in `ModelCache.unload` before returning (so delete/replace of the file succeeds). Same risk for pull.py:210/241 `os.replace(part, dest)` when re-pulling a model that is loaded (dest mmapped -> PermissionError WinError 5/32). Fix: manager.pull must `unload` repo first (or catch PermissionError -> clear "model in use, unload it" ModelBusyError); wrap os.replace in a 5x retry/backoff (AV scanners/Defender also briefly lock fresh files).

## MEDIUM
3. models/store.py:110 registry.json `os.replace(tmp, manifest)`: atomic on NTFS but raises PermissionError if a reader (UI/AV/indexer) has it open at that instant; `_read` swallows OSError -> returns {} (looks like empty registry; next write would WIPE it). Fix: retry os.replace 5x w/ 50ms backoff; in `_read`, distinguish FileNotFound from other OSError (don't return {} on PermissionError, retry). Fixed `.tmp` name also races between two processes: use `tempfile.mkstemp(dir=models_dir)`.
4. Path length (MAX_PATH 260): models_dir is relative `.dana/models`; dir `litert-community__whisper-tiny` + nested HF file paths (safe_relpath allows subfolders) can exceed 260 under deep user profile (`C:\Users\<long>\AppData\...`). Python 3.13 on Win10 1607+/11 honours long paths only if LongPathsEnabled registry set (not default for non-store python). Fix: in model_dir/dest use `\\?\` prefix on win32 (`os.path.abspath` + prefix) or document + doctor check; keep nested depth <=2.
5. mcp.py:98 stdio_client on Windows: needs Proactor loop. asyncio.run on 3.13 Windows defaults to Proactor (OK) — BUT Pipecat/uvicorn: uvicorn (control server) on Windows `loop="auto"` uses Proactor in uvicorn>=0.?? only when not `--reload`; with `--reload`/workers it forces Selector -> `NotImplementedError` creating subprocess. Fix: never pass reload; add assert/log of `type(asyncio.get_running_loop()).__name__` in MCPActions.connect and fail with clear message if Selector. mcp SDK also wants `command` to be resolvable: npx/uvx on Windows are `.cmd` -> pass `cmd /c npx` or the mcp SDK's get_default_environment; document in MCPServerConfig example (`command="npx.cmd"`).
6. models_routes.py:199-215 `/api/v1/models/file?repo_id=&path=`: Windows-style paths from UI (`a\b.tflite`, `C:\x`) are rejected by `safe_relpath` (backslash / drive letter) -> 400/422. That's correct security-wise; UI must send repo-relative POSIX paths from `rec.files[].path` (never from disk paths). Verify dana-ui/src/api/models.ts builds URL with encodeURIComponent(path) from the manifest, not from `local_path`. Also manager.file_path should `resolve()` and assert `is_relative_to(model_dir)` (Windows case-insensitivity/8.3 short names/junctions; compare with `os.path.normcase`).
7. Filename chars: repo ids map `/`->`__` (fine). HF filenames may contain `:`? Rare; `safe_relpath` doesn't reject `<>:"|?*`, trailing dot/space, or reserved names (CON, NUL, AUX). `a:b.tflite` on NTFS creates an alternate data stream silently! Fix: in safe_relpath reject any `[<>:"|?*]`, control chars, trailing `.`/space, and reserved device names per segment (the existing `^[A-Za-z]:` check only catches the leading drive).

## LOW / notes
8. `.part` resume (pull.py:203-241): fine; `with part.open` closed before replace (good). `part.stat().st_size` after crash: OK. Defender may hold `.part` -> covered by retry in #2. Open-file `unlink` at 206/221 can also PermissionError: use missing_ok + retry.
9. litert num_threads default 4 (config.py:71): ok; on 4-core/hybrid Win laptops (E-cores) prefer `min(4, os.cpu_count()//2)`; LiteRT win_amd64 wheels exist for cp311-cp314 incl. cp313 (uv.lock verified: ai_edge_litert 2.3.0 cp313 win_amd64 present). numpy dtypes: runtime uses `np.asarray(arr, dtype=d["dtype"])` - explicit dtype, OK; beware numpy default int is int32 on Windows for numpy<2 (int64 on numpy>=2): any `np.array([ids])` without dtype in stt/tts litert token code would yield int32 on numpy 1.x. Check/force `dtype=np.int64` where models expect int64 (set_tensor strict dtype).
10. piper: uv.lock has piper-tts 1.6.1 cp39-abi3 win_amd64 wheel (verified) - wheels bundle espeak-ng data (piper 1.3+ ships `espeakbridge` + espeak-ng-data inside the package), so no system espeak needed. onnxruntime win_amd64 present in lock (6 entries). piper.py:77 passes `str(model)` and explicit config_path: fine. Path with non-ASCII user dir (Vietnamese usernames e.g. `C:\Users\Nguyễn`) - onnxruntime on win accepts wide-char paths; espeak-ng data path with non-ASCII historically broken in espeak C lib -> if piper fails, test with a non-ASCII profile (live Windows check).
11. os_win.py:151-176 pywinauto: single worker thread, lazy `importlib.import_module("pywinauto")` inside `_snapshot` (runs on dana-uia thread) -> comtypes initialises COM (MTA via CoInitializeEx) on that thread at first import: correct. Risk: if `pywinauto` was already imported on main thread elsewhere (e.g. keyboard actions), the worker thread has NO CoInitialize -> `OSError -2147221008 CoInitialize has not been called`. Fix: in worker init (`ThreadPoolExecutor(initializer=...)`) call `pythoncom/comtypes.CoInitializeEx(COINIT_MULTITHREADED)`; do not mix with pywinauto's default STA/MTA mismatch (set `sys.coinit_flags = 2` before first comtypes import).
12. scripts/serve_sglang.ps1: `wsl wslpath -a ($script -replace '\\','/')` OK (wslpath accepts C:/..). `Resolve-Path` of a path with spaces handled (passed as one arg). `wsl env "MODEL=$Model" ... bash $wslPath`: $wslPath with spaces would be word-split by PowerShell->wsl argv -> quote: `bash "'$wslPath'"`; simpler `wsl -e bash -lc` is worse; use `wsl -e env ... bash -- "$wslPath"`. Also `$Model` containing `/` fine. Script file must have LF endings (.sh checked out CRLF with autocrlf -> `bash: \r: command not found`): add `*.sh text eol=lf` in .gitattributes. [Medium]
13. pyproject: `pywinauto>=0.6.8; sys_platform == 'win32'` marker correct; uv.lock is universal so win entries are present (litert/piper/onnxruntime verified). `pywinauto` pulls comtypes/pywin32 - confirm in lock (not checked). tflite_runtime fallback in runtime/litert.py:22 has no Windows wheels (harmless).
14. Signals: `__main__` guards POSIX signals (CLAUDE.md); Ctrl+C under Proactor asyncio.run raises KeyboardInterrupt only at next loop wake - acceptable.
